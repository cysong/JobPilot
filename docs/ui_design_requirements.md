# JobPilot UI 设计需求

## 1. 设计理念与主题
*   **主题**: 现代 PaaS (平台即服务) 美学。整洁、专业、值得信赖，同时兼具创新感。
*   **核心概念**: "您的 AI 求职助手"。UI 应给人一种智能工作区的感觉，而不仅仅是一个数据表格。
*   **视觉风格**:
    *   **配色方案**: 专业的蓝色/靛蓝色 (信任感) 混合充满活力的点缀色 (AI/创新 - 例如紫罗兰色或青色渐变)。
        *   **Primary**: Indigo/Violet (`#4f46e5` / `violet-600`)
        *   **Background**: Slate/Gray (`slate-50` for app bg, `white` for cards)
    *   **排版**: 整洁的无衬线字体 (Inter, Roboto 或类似字体)，以确保高可读性。
    *   **布局**: 宽敞、卡片式设计，使用玻璃拟态或微妙的阴影来增加深度。
    *   **交互**: 流畅的过渡动画，用于反馈的微交互 (例如按钮悬停、加载状态)。
*   **深色模式**: 全面支持 (跟随系统/用户偏好)。

## 2. 技术实现规范 (Frontend Stack)
为了保证设计的一致性和开发效率，前端采用以下技术栈和规范：

*   **组件库**: **shadcn/ui** (基于 Radix UI + Tailwind CSS)。
    *   *原则*: 拥有代码的所有权，直接将组件代码复制到 `src/components/ui` 中进行定制。
*   **样式系统**: **Tailwind CSS**。
    *   使用 `clsx` 和 `tailwind-merge` 处理样式冲突和条件样式。
    *   使用 `class-variance-authority (cva)` 管理组件变体。
*   **图标库**: **Lucide React** (风格统一，Tree-shakable)。
*   **表单处理**: **React Hook Form** + **Zod**。
    *   所有表单必须有 Schema 定义。
    *   必须提供实时验证反馈。

## 3. 通用 UI 模式与最佳实践

### 3.1 布局 (Layout)
*   **Dashboard Layout**: 侧边栏 + 顶部导航 + 内容区域。
*   **Auth Layout**: 分屏设计 (Split View) 或 中心卡片 (Centered Card)。
    *   *Split View*: 左侧为品牌/营销内容，右侧为功能表单。

### 3.2 交互反馈 (Feedback)
*   **加载状态**:
    *   按钮点击后必须显示 Loading Spinner，并禁用点击。
    *   数据加载使用 Skeleton (骨架屏) 而非简单的 "Loading..." 文字。
*   **错误处理**:
    *   表单字段错误：在输入框下方显示红色文字。
    *   全局/API错误：使用 **Toast** (右上角弹出) 通知。
*   **成功提示**:
    *   操作成功后使用 Toast 提示 (如 "登录成功", "保存成功")。

### 3.3 表单设计 (Forms)
*   **验证**: 采用 Zod Schema 进行严格验证。
*   **实时性**: 关键字段 (如密码强度、用户名可用性) 提供实时反馈。
*   **可访问性**: 确保所有 Input 都有对应的 Label，支持键盘导航。

## 4. 全局导航
*   **顶部栏**:
    *   **Logo**: "JobPilot" (左侧)。
    *   **主导航**: 仪表盘, 职位, 简历, 个人资料 (中间/右侧)。
    *   **用户菜单**: 头像, 设置, 登出。
    *   **通知**: 铃铛图标，用于实时更新 (申请状态变更)。
    *   **配额/积分**: 微妙展示剩余的 AI 积分 (针对 VIP/免费用户)。

## 5. 落地页 (公开)
*   **首屏区域 (Hero Section)**:
    *   **主标题**: "用 AI 驱动的精准度，斩获您的梦想职位。"
    *   **副标题**: "自动简历定制、求职信生成和智能职位匹配。"
    *   **CTA (行动号召)**: "免费开始" / "登录"。
    *   **视觉图**: AI 将候选人与职位匹配的抽象表现，或仪表盘样机。
*   **功能区域**:
    *   **智能匹配**: "匹配度评分" 可视化。
    *   **自动定制**: "一键简历定制"。
    *   **申请追踪**: "求职看板"。
*   **社会证明 / 信任**: "由先进的 LLM 驱动"。
*   **页脚**: 文档, 隐私政策, 条款链接。

## 6. 仪表盘 (登录后主页)
*   **概览卡片**:
    *   **进行中的申请**: 进行中的申请数量。
    *   **面试**: 即将到来的面试数量。
    *   **Offer**: 成功获得的 Offer 数量。
*   **最近活动 / 时间轴**:
    *   可滚动的最近操作列表 (例如 "已为 Google 定制简历", "已向 Microsoft 发送申请")。
*   **快捷操作**:
    *   "搜索职位", "上传简历"。

## 7. 职位搜索与发现
*   **搜索头部**:
    *   **关键词**: 输入框。
    *   **筛选器**: 地点 (远程/混合/现场), 雇佣类型, 薪资范围, 公司。
*   **职位列表 (卡片)**:
    *   **卡片内容**: 职位名称, 公司 (Logo), 地点, 薪资, 发布日期。
    *   **徽章**: "远程", "急招" (P1), "高匹配" (P0 - >90%)。
    *   **匹配度评分**: 匹配程度的视觉指示器 (例如环形图)。
    *   **操作**: "保存/加入待办", "查看详情"。
*   **职位详情视图**:
    *   **头部**: 关键信息 + "申请 / 加入列表" 按钮。
    *   **描述**: 可折叠的长文本。
    *   **分析 (AI)**:
        *   **技能匹配**: 匹配 vs 缺失技能的可视化细分。
        *   **洞察**: AI 对该职位的总结。
    *   **相似职位**: "该公司其他职位" 侧边栏/底部区域。

## 8. 我的申请 (申请管理)
*   **视图**:
    *   **看板 (Kanban)** (P1): 待办, 定制中, 就绪, 已投递, 面试中, Offer, 已拒绝等列。支持拖拽。
    *   **列表视图**: 可排序的表格 (日期, 状态, 公司)。
*   **申请详情页**:
    *   **状态头部**: 当前状态步骤条 (待办 -> ... -> Offer)。
    *   **定制设置 (待办状态)**:
        *   **简历选择**: 可用简历的下拉菜单/列表。高亮显示 **"系统推荐"** 的简历。
        *   **定制深度**: "深度定制" vs "轻度定制" 的单选按钮 (默认基于 Profile 设置)。
    *   **时间轴**: 所有事件的垂直时间轴 (创建, 已定制, 已投递, 备注)。
    *   **材料区域**:
        *   **简历**: 链接到定制后的 PDF/Markdown。
        *   **求职信**: 预览与编辑。
        *   **质量检查**: AI 反馈结果 (警告/通过)。
    *   **操作**: "标记为已投递", "下载全部", "添加备注"。

## 9. 简历管理
*   **简历列表**:
    *   每个简历版本的卡片。
    *   "草稿" vs "定稿/模板" 的指示器。
    *   "新建" 按钮。
*   **编辑器 (Markdown)**:
    *   **分屏视图**: 编辑器 (左) vs 预览 (右)。
    *   **工具栏**: 基础格式化。
    *   **AI 助手 (侧边栏)**: "分析简历", "优化措辞" 建议。
*   **预览**:
    *   Markdown 的整洁、专业渲染。
    *   下载 PDF 按钮。

## 10. 用户个人资料与设置
*   **个人信息**: 姓名, 职位头衔, 联系方式。
*   **技能矩阵**:
    *   带有熟练度等级的技能列表。
    *   "AI 提取" vs "手动添加" 指示器。
*   **偏好设置 (AI 配置)**:
    *   **定制风格**: "强调领导力", "侧重技术能力"。
    *   **默认定制偏好**: 选择默认模式 (深度/轻度)。
    *   **求职信语气**: "正式", "热情", "自信"。
*   **订阅与用量**:
    *   当前计划 (免费/VIP)。
    *   用量统计 (本月使用的 Token/申请数)。

## 11. 移动端适配
*   所有页面必须完全响应式。
*   **移动端导航**: 汉堡菜单或底部 Tab 栏。
*   **复杂视图**: 看板在移动端可切换为列表视图。

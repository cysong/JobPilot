# JobPilot 渐进式开发计划

## 总体策略

本开发计划遵循"可用优先、逐步完善"的原则，每个版本都是完整可演示的系统，从最简单的端到端流程开始，逐步增强功能深度和用户体验。每个版本变更成本小，过渡自然，确保系统始终处于可用状态。

### 核心原则

1. **端到端优先**: 先建立完整的业务闭环，再优化细节
2. **渐进增强**: 每个版本在上一版本基础上扩展，不推倒重来
3. **独立验证**: 每个版本都有明确的业务价值和可演示的功能
4. **最小变更**: 版本间的差异控制在可管理范围内
5. **真实数据**: 从 v0.1 开始就使用真实的 Job 数据源

## Version 0.1 - 核心原型 (Foundation)

### 里程碑定义
建立最基础的端到端流程：用户能够浏览 Job、创建申请、获得 AI 定制的简历和求职信。这是整个系统的"骨架"。

### 业务价值
- 验证核心技术架构可行性
- 演示完整的 AI 辅助申请流程
- 获得用户对核心功能的反馈

### 核心功能

#### 1. 基础认证 (Auth)
- 用户注册/登录 (JWT)
- 单一角色 (USER)
- 无配额限制

#### 2. Job 浏览 (只读)
- 简单列表展示 (固定分页 20 条)
- 基础字段：标题、公司、地点、发布时间、描述摘要
- 单一排序：按发布时间倒序
- **无筛选、无搜索**

#### 3. 简历管理 (简化版)
- 创建/编辑简历 (Markdown)
- 草稿/正式状态切换
- **无版本历史、无 AI 分析**
- **无数量限制**
- 下载 PDF (使用默认模板)

#### 4. 申请创建 (核心流程)
- 从 Job 详情页"加入申请"
- 用户手动选择一份正式简历
- **固定使用 Light Tailoring**
- 状态流转：Pending → Tailoring → Ready
- **无时间线、无备注**

#### 5. AI Agent (最简实现)
- **仅实现两个任务**：
  - `tailor_resume`: 简历定制 (Deep)
  - `generate_cover_letter`: 求职信生成
- 使用 OpenAI GPT-4 (单一模型)
- **无质量检查、无重试机制**
- 结果直接写入 Document 表

#### 6. Workflow (串行执行)
- **串行工作流**：tailor_resume → generate_cover_letter
- Celery 任务队列
- **无进度推送、无 WebSocket**
- 任务完成后更新 Application 状态

#### 7. 申请管理
- 简单列表 (按更新时间排序)
- 查看定制简历和求职信
- 下载 PDF
- **无状态更新、无编辑功能**

### 数据模型 (简化版)

#### 涉及的表
- `users` (基础字段)
- `seek_jobs` (只读)
- `resumes` (无软删除)
- `documents` (链式版本，最简实现)
- `applications` (核心字段)
- `ai_usage` (仅记录 token 使用)

#### 暂不实现的表
- `job_analysis`
- `job_matches`
- `user_skills`
- `timeline_events`
- `interview_prep`

### 技术栈决策
- 前端：React + Vite + shadcn/ui + Zustand
- 后端：FastAPI + SQLAlchemy + Celery
- AI：OpenAI GPT-4 (通过 spec-kit Gateway)
- 数据库：PostgreSQL
- 缓存/队列：Redis

### 工作量估算
**规模**: 小型 (约 2-3 周单人开发)

**复杂度**:
- 前端：3 个页面 (Job 列表、简历管理、申请管理)
- 后端：4 个模块 (auth, jobs, resumes, applications)
- AI Agent：2 个任务
- 工作流：串行 Celery 任务

### 验收标准
- [ ] 用户可以注册并登录
- [ ] 用户可以浏览 Job 列表并查看详情
- [ ] 用户可以创建简历并标记为正式版本
- [ ] 用户可以创建申请并选择简历模板
- [ ] 系统自动生成定制简历和求职信
- [ ] 用户可以查看和下载生成的材料

## Version 0.3 - 智能匹配 (Smart Matching)

### 里程碑定义
引入 AI 分析能力：自动分析 Job 要求、提取用户技能、计算匹配度，并推荐最佳简历。

### 业务价值
- 帮助用户快速识别合适的职位
- 自动推荐最佳简历，减少选择成本
- 为后续筛选和排序功能打基础

### 新增功能

#### 1. 简历技能分析
- 用户将简历标记为正式版本时触发
- AI 提取技能并自动填充 `user_skills` 表
- 技能分类：technical/soft/industry
- 熟练度等级：Beginner/Intermediate/Advanced/Expert
- 用户可手动编辑技能

#### 2. Job 分析 (定时任务)
- Celery Beat 定时任务 (每小时执行)
- 分析过去一周内新增的 Job
- 提取必备/可选/软技能
- HTML→Markdown 转换
- 翻译为中文 (使用 DeepSeek)
- 提取工作年限、申请截止日期
- 结果存入 `job_analysis` 表

#### 3. 匹配度计算
- Job 分析完成后，触发匹配计算
- 与所有用户的技能库计算匹配度
- 算法：必备技能完全匹配 70%，可选/软技能 30%
- 结果存入 `job_matches` 表
- **匹配度 ≥ 60% 时，触发简历推荐任务**

#### 4. 简历推荐
- 新增 AI 任务：`resume_recommendation`
- 输入：用户所有正式简历 + Job 要求
- 输出：bestMatchedResumeId + matchDetails
- 存储到 `job_matches.bestMatchedResumeId`

#### 5. 前端展示增强
- Job 列表卡片显示匹配度标签
- 匹配度 ≥ 90% 显示"高匹配"徽标
- Job 详情页显示匹配详情
- 创建申请时自动带出推荐简历 (可修改)

### 数据模型变更
- **新增表**: `job_analysis`, `job_matches`, `user_skills`
- `applications` 表增加字段：`recommendedResumeId` (系统推荐) vs `sourceResumeId` (用户选择)

### 工作量估算
**规模**: 中型 (约 2-3 周单人开发)

**复杂度**:
- AI Agent：3 个新任务 (skill_extraction, job_analysis, resume_recommendation)
- 定时任务：Celery Beat 配置
- 匹配算法：技能匹配逻辑
- 前端：技能库管理页面 + 匹配度展示

### 验收标准
- [ ] 用户定稿简历时自动提取技能
- [ ] 技能库页面可查看和编辑技能
- [ ] 定时任务自动分析新 Job
- [ ] Job 列表显示匹配度
- [ ] 创建申请时自动推荐最佳简历
- [ ] 可对比推荐简历和用户选择的差异

## Version 0.5 - 申请生命周期 (Application Lifecycle)

### 里程碑定义
完善申请管理：支持完整的状态流转、时间线追踪、材料编辑和批量操作。

### 业务价值
- 用户可以管理整个求职流程 (从申请到 Offer)
- 提供审计轨迹和历史回溯能力
- 支持真实的求职场景操作

### 新增功能

#### 1. 完整状态流转
- 扩展状态：Pending → Tailoring → Ready → Applied → PhoneScreen → Interviewing → Offer/Rejected
- 状态手动更新 (下拉选择)
- 状态变更时记录时间线事件

#### 2. 时间线追踪
- 新增 `timeline_events` 表
- 记录事件类型：
  - created
  - status_changed (包含前后状态)
  - note_added
  - material_generated
  - material_edited
- 时间线页面按时间倒序展示

#### 3. 材料编辑
- Ready 状态下允许编辑定制简历和求职信
- 编辑时创建新 Document 版本 (parentId 指向上一版本)
- Applied 状态后锁定材料 (不可编辑)
- 显示编辑历史和版本对比

#### 4. 申请备注
- 用户可为申请添加备注
- 备注记录到 timeline_events
- 支持富文本 (Markdown)

#### 5. 批量操作
- 批量标记为 Applied 状态
- 批量删除 (软删除)

#### 6. 软删除与恢复
- 申请软删除 (isDeleted 标记)
- 再次申请同一 Job 时恢复记录

### 数据模型变更
- **新增表**: `timeline_events`
- `applications` 表增加字段：`isDeleted`, `deletedAt`
- `documents` 表完善版本链 (parentId)

### 工作量估算
**规模**: 中型 (约 2 周单人开发)

**复杂度**:
- 前端：状态选择器 + 时间线组件 + 编辑器集成
- 后端：版本管理逻辑 + 批量操作 API
- 业务逻辑：状态流转规则 + 锁定机制

### 验收标准
- [ ] 用户可以更新申请状态到任意阶段
- [ ] 时间线清晰记录所有操作历史
- [ ] Ready 状态下可编辑材料
- [ ] Applied 后材料被锁定
- [ ] 可查看材料的版本历史
- [ ] 批量操作至少 10 条申请无性能问题

## Version 0.6 - 质量保证 (Quality Assurance)

### 里程碑定义
引入自动质量检查和材料重新生成机制，确保申请材料的专业性。

### 业务价值
- 减少人为错误 (如公司名错误)
- 提升材料质量和一致性
- 给用户提供改进建议

### 新增功能

#### 1. 自动质量检查
- 新增 AI 任务：`quality_check`
- 在 Cover Letter 生成后自动触发
- 检查项：
  - 公司名称一致性 (与 Job 对比)
  - 技能覆盖率 (必备技能 ≥ 70%)
  - 格式规范性
- 结果存储到 `applications.resumeVerified` 和 `coverLetterVerified`

#### 2. 质量问题展示
- 申请详情页显示质量检查结果
- 警告/提示分级 (Error/Warning/Info)
- 用户可选择"忽略"或"重新生成"

#### 3. 材料重新生成
- Ready 状态下支持重新生成简历或求职信
- 重新生成时：
  - 创建新 Document (parentId 指向模板，rootId 保持不变)
  - 保留历史版本
  - 重新执行质量检查
- 前端显示"重新生成"按钮

#### 4. 文件命名规范
- 下载 PDF 时自动生成专业文件名
- 格式：`{UserName}_Resume_{JobTitle}.pdf`
- 格式：`{UserName}_CoverLetter_{JobTitle}.pdf`

#### 5. 工作流优化
- 将工作流改为并行执行：
  ```
  开始 ─┬─ tailor_resume ─┬─ quality_check → 完成
         └─ generate_cover_letter ─┘
  ```
- 使用 Celery Chord 实现

### 数据模型变更
- `applications` 表增加字段：`resumeVerified`, `coverLetterVerified`

### 工作量估算
**规模**: 中型 (约 1-2 周单人开发)

**复杂度**:
- AI Agent：质量检查逻辑
- 工作流：串行改并行 (Celery Chord)
- 前端：质量报告展示 + 重新生成交互

### 验收标准
- [ ] 简历和求职信生成后自动质量检查
- [ ] 检查结果在详情页清晰展示
- [ ] 用户可重新生成单个材料
- [ ] 重新生成保留历史版本
- [ ] PDF 文件名符合专业规范
- [ ] 并行执行比串行快至少 30%

## Version 0.7 - 定制策略 (Customization Strategy)

### 里程碑定义
引入可配置的定制深度和用户偏好预设，满足不同场景需求。

### 业务价值
- 用户可根据职位重要性选择定制策略
- 节省高价值职位的定制时间
- 降低一般职位的 AI 成本

### 新增功能

#### 1. 定制深度选择
- 支持两种策略：
  - **Deep Tailoring**: 全面重写个人简介、工作经历
  - **Light Tailoring**: 仅关键词对齐和最小调整
- 创建申请时用户可选择 (默认使用 Profile 预设)
- 记录到 `applications.tailoringLevel`

#### 2. 用户 Profile 预设
- 用户可设置默认定制策略偏好
- 设置简历定制偏好 (强调技术深度/管理经验等)
- 设置 Cover Letter 风格偏好
- 存储到 `users.preferences` (JSON)

#### 3. AI Prompt 模板化
- 定制策略对应不同的 Prompt 模板
- Deep 模板：详细指令，强调对齐和重写
- Light 模板：简化指令，保留原文为主
- 存储在 `prompts/` 目录

#### 4. 预设自动带出
- 创建申请时自动填充用户 Profile 预设
- 用户可针对具体职位调整

### 数据模型变更
- `users` 表字段：`preferences` (JSON)
- `applications` 表字段：`tailoringLevel` (已有)

### 工作量估算
**规模**: 小型 (约 1 周单人开发)

**复杂度**:
- AI Agent：Prompt 模板切换逻辑
- 前端：Profile 设置页面 + 策略选择器
- 后端：Preferences API

### 验收标准
- [ ] 用户可在 Profile 中设置默认策略
- [ ] 创建申请时自动应用预设
- [ ] 可针对单个申请修改策略
- [ ] Deep 和 Light 生成的材料有明显差异
- [ ] Light 策略的 token 消耗明显更低

## Version 0.8 - 角色与配额 (Role & Quota)

### 里程碑定义
引入多角色权限和配额管理机制，支持商业化运营。

### 业务价值
- 支持免费/付费用户分层
- 控制成本和滥用风险
- 为商业化打基础

### 新增功能

#### 1. 角色权限
- 扩展 `users.role`: USER/VIP/ADMIN
- 角色限制：
  - **USER**: 正式简历 3 份，每月申请 20 个，AI 使用量受限
  - **VIP**: 正式简历 10 份，每月申请不限，AI 使用量更高
  - **ADMIN**: 无限制
- 全局配置 `FORMAL_RESUME_LIMIT` (环境变量)

#### 2. 配额管理
- `users` 表增加字段：
  - `monthlyJobLimit`: 每月 Job 分析配额
  - `monthlyTokenLimit`: 每月 Token 配额
  - `monthlyTokenLeft`: 剩余 Token 数
  - `quotaResetAt`: 配额重置时间
- AI 使用量精确统计 (input/output/cache tokens)

#### 3. 配额检查与扣除
- **检查时机** (API Layer): 创建申请前检查配额
- **扣除时机** (Outbox Layer): AI 任务成功后扣除
- 配额不足时返回友好错误提示

#### 4. 配额重置
- Celery Beat 定时任务 (每月 1 日 0:00)
- 重置 `monthlyTokenLeft`
- 更新 `quotaResetAt`

#### 5. 配额展示
- Profile 页面显示当前配额使用情况
- 进度条展示剩余额度
- 接近上限时预警

#### 6. WebSocket 配额预警
- 剩余配额 < 10% 时推送预警消息

### 数据模型变更
- `users` 表增加配额相关字段
- `ai_usage` 表完善 token 记录

### 工作量估算
**规模**: 中型 (约 2 周单人开发)

**复杂度**:
- 后端：配额检查/扣除逻辑 + 定时任务
- 前端：配额展示组件 + 预警提示
- 中间件：权限检查拦截器

### 验收标准
- [ ] 不同角色有正确的配额限制
- [ ] 配额不足时无法创建申请
- [ ] AI 使用后正确扣除配额
- [ ] 每月自动重置配额
- [ ] Profile 页面准确显示剩余配额
- [ ] 配额预警通过 WebSocket 实时推送

## Version 1.0 - 面试准备 (Interview Preparation)

### 里程碑定义
自动生成面试准备材料，帮助用户应对技术面试和行为面试。

### 业务价值
- 提供一站式求职服务
- 提升用户面试通过率
- 增强产品竞争力

### 新增功能

#### 1. 面试准备自动触发
- 当申请状态变更为 Interviewing 时自动触发
- 生成三类材料：
  - 公司常见面试题
  - 技术知识点复习清单
  - STAR 行为面试准备

#### 2. 公司面试题库
- 基于公司研究 (未来扩展) 或通用模板
- 提炼技术面试常见题型
- 同一公司的多个申请共享题库

#### 3. 技术复习清单
- 基于 Job 必备/可选技能
- 生成技术大纲 + 推荐资源链接
- 相同技能要求的 Job 共享清单

#### 4. STAR 行为面试
- 从用户所有简历中提取工作经历
- 生成 STAR 格式草稿 (Situation/Task/Action/Result)
- 用户可编辑和补充

#### 5. 面试准备材料管理
- 新增 `interview_prep` 表
- 跨 Job 共享 (按公司或技能聚合)
- 版本化 (用户编辑后保留历史)
- 查看和编辑界面

### 数据模型变更
- **新增表**: `interview_prep`
- 关联关系：`user_id` + `company_name` 或 `skill_set_hash`

### 工作量估算
**规模**: 中型 (约 2-3 周单人开发)

**复杂度**:
- AI Agent：新增 `interview_prep_generation` 任务
- 前端：面试准备页面 + 编辑器
- 后端：跨 Job 共享逻辑 + 版本管理

### 验收标准
- [ ] 申请进入 Interviewing 状态时自动生成材料
- [ ] 面试准备材料包含三类内容
- [ ] 同一公司的申请共享面试题库
- [ ] 用户可编辑 STAR 答案
- [ ] 编辑历史可回溯

## Version 1.1 - AI 简历优化 (Resume Optimization)

### 里程碑定义
在简历管理模块引入 AI 分析和优化建议，帮助用户改进简历模板质量。

### 业务价值
- 提升简历模板基础质量
- 减少定制简历的修改需求
- 增强 AI 能力的可见性

### 新增功能

#### 1. AI 一键分析
- 简历编辑页面新增"分析"按钮
- 支持自定义提示词 (可选)
- AI 生成多条优化建议 (标题 + 简述)

#### 2. 建议类型
- 措辞优化 (更专业/更有力)
- 量化成果补充 (数字化描述)
- 结构微调 (段落重组、重点突出)
- 技能关键词建议

#### 3. 建议应用
- 用户勾选建议后"一键应用"
- 应用前显示原文对照 (侧边或分栏对比)
- 应用后自动保存新版本
- 建议记录到 Document.changeComments

#### 4. 简历质量评分
- 定稿时 AI 自动评分 (0-100)
- 评分维度：完整性、专业性、量化程度、关键词覆盖
- 评分结果存储到 Document.metadata

### 数据模型变更
- `documents` 表字段：`metadata` (已有，增加 `qualityScore`)

### 工作量估算
**规模**: 中型 (约 1-2 周单人开发)

**复杂度**:
- AI Agent：新增 `resume_analysis` 任务
- 前端：建议列表 + 对比视图 + 应用逻辑
- 后端：建议管理 API

### 验收标准
- [ ] 用户可一键分析简历
- [ ] 生成的建议具体且可操作
- [ ] 用户可勾选并应用建议
- [ ] 应用前可查看原文对照
- [ ] 定稿时自动评分并记录

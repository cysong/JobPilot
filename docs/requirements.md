# JobPilot需求文档

这是一个匹配用户简历与工作需求并通过ai进行简历定制，生成求职信，和管理申请流程的系统


## 用户使用流程
- job信息由外部爬虫系统定期从招聘网站爬取，本系统只读访问
- 用户注册后可以新建或者上传简历，初始为草稿状态，简历title使用岗位名称
- 用户可以使用ai分析简历并给出专业修改建议并带上优先级
- 简历定稿后成为正式简历，正式简历可以下载pdf，可以匹配job
- 定稿的时候使用ai分析简历提取其中提到的技能并按照简历id保存到个人技能库
- 定稿的时候使用ai分析简历，并对简历的质量进行评分
- 定时任务分析最新的job信息（例如一天内），提取必须、可选、软技能并存储，将job正文转为markdown，并翻译为中文
- 定时任务将最新的job信息（例如一天内）与用户的简历岗位进行匹配，只有匹配的job进入下一步
- 将上一步匹配的job所需的技能信息与用户的技能库进行匹配计算匹配度并记录
- 匹配度超过阈值（例如50%）的岗位再将job信息与用户的简历（ai评分超过阈值）进行匹配，选择最佳匹配简历（必须超过设定的阈值）并记录
- 当用户在前台根据匹配度将job加入待申请列表
- 后台收到请求创建新的申请列表并发布事件
- 根据事件创建任务（定制简历，生成cover letter）并加入任务队列
- 任务执行并更新任务状态，每个阶段根据申请id向前台广播任务进度，记录llm模型调用
- 全部任务执行完成更新申请状态为ready，并向前台实时发送通知
- 当申请状态ready之后用户可以修改定制的简历和cover letter
- 用户下载pdf版本简历和cover letter并访问job发布网站手动申请job
- 用户标记申请状态为applied，不可再修改定制简历和cover letter
- 用户收到招聘方电话、面试通知、offer的时候更新申请状态

## job

### job展示与搜索 【P0】
job信息来自于另外一个系统，这个系统只读取job信息。
职位展示模块用于聚合并呈现来自多平台的英文职位，支持服务器端分页（每页 20 条）与按职位发布时间倒序的"最新"排序。用户可通过地点、用工类型、薪酬、公司与发布时间区间进行筛选，并可在标题与描述内进行关键词搜索。远程/混合/现场分类与去重由爬虫预处理，本模块仅基于标准化结果展示。支持在列表或详情页将职位加入"待申请"，并在职位卡片显示申请状态；详情页提供同公司其他岗位与外链跳转。UI 文案采用英文，当前以新西兰市场为主，同时保留未来国际化扩展能力。
- 列表与分页
  - 使用服务器端分页，固定每页 20 条。
  - 默认按“最新”排序（按职位发布时间倒序）。
  - 翻页与筛选组合后返回列表需保留筛选与滚动位置。
- 展示字段（列表）
  - 标题、公司名、地点（城市/国家或 Remote/Hybrid/Onsite）、用工类型（全职/兼职/合同/实习）、来源平台、职位发布时间、描述摘要（2-3 行截断）。
  - 薪资：若存在按原始文本展示；若缺失显示"面议"；不做币种换算。
  - 申请状态：若已加入"待申请/已申请/面试/Offer/拒绝"，在卡片显著位置显示状态徽标。
  - 匹配度标签：显示与用户技能仓库的匹配百分比；匹配度≥90%显示"高匹配"徽标。【P0】
  - 紧急度标签：基于职位发布时间与申请截止日期（若有）计算紧急度，标记"紧急"徽标。【P1】
- 远程分类
  - Remote/Hybrid/Onsite 由爬虫在入库前完成归类；前端仅依据该标准化值展示与筛选。
- 去重与来源
  - 去重由爬虫处理；同一岗位仅展示第一条记录；不合并多来源、不显示来源计数。
- 筛选与搜索
  - 筛选项：地点（可多选，含 Remote/Hybrid/Onsite）、用工类型（全职/兼职/合同/实习）、公司（可多选）、发布时间区间（如 24 小时内 / 7 天内 / 自定义）。
  - 关键词搜索：覆盖标题与描述，命中词高亮。
  - 无结果：仅显示合理英文提示（例如 “No results. Try widening filters.”）。
- 交互
  - 列表卡片内提供“一键加入待申请”；若已加入则显示状态并避免重复加入。
  - 点击卡片进入详情页；详情页提供“前往原链接”跳转（离站提示）。
  - 提供入口跳转到“我的申请”页面。
- 详情页
  - 展示与列表一致的基础字段与完整描述；长文本默认折叠并可展开。
  - 底部展示“同公司其他岗位”（约 5 条，按最新排序），并提供“查看全部”跳转。
  - 详情页同样支持“加入待申请”并显示当前状态。
- 文案与国际化
  - UI 文案使用英文；职位内容为英文（当前主要支持新西兰市场）。
  - 暂不提供多语言界面，但保留未来国际化扩展能力。
- 可达性与反馈
  - 空态与错误状态提供英文提示；


### job分析 【P0】
通过定时任务（每小时执行一次）自动分析新增job，筛选条件为过去一周内新增的记录。分析结果存入独立表，外键关联到job表。
- 内容转换：将HTML描述转为Markdown并保存；转换失败时记录错误信息，需人工介入。
- 翻译：使用翻译接口或LLM将英文描述翻译为中文并保存，支持详情页中英文切换显示。
- 技能提取：使用LLM从Markdown提取必备技能、可选技能、软技能及其他要求（如工作年限、申请截止日期），用于匹配度与紧急度计算。
- 数据生命周期：外部系统与本系统共享数据库，job仅新增不删除；本系统job为软删除，已生成的材料保持不变。

### 匹配分析 【P0】
job分析完成后，预计算该job与所有用户的技能仓库的匹配度并存储结果。匹配算法（当前仅支持技术岗位）：必备技能完全匹配得70%基础分，可选技能与软技能匹配程度贡献剩余30%。匹配分数以百分比形式在job列表与详情页展示，辅助用户决策是否加入申请。
对于匹配度高于阈值的简历（例如60%），继续分析用户的简历与job的匹配度，选择最佳匹配的简历作为推荐给用户的简历，当用户将job加入待申请时，自动选择推荐的简历，但是允许用户自由选择简历模板，用户选择的模板也要一并记录，进行后续对比分析。

### 紧急度评分 【P1】
基于职位发布时间与申请截止日期（若有）自动计算紧急度评分，用于生成"紧急申请清单"视图。
- 评分规则：发布时间越久或距离截止日期越近，紧急度越高。
- 紧急申请清单：在"我的申请"中提供专门视图，仅展示Pending/Tailoring/Ready状态且紧急度高的申请，按紧急度排序。

## 我的申请 【P0】
用于管理用户对职位的申请全流程：从"加入待申请"开始，自动触发研究与材料定制，记录所有状态与备注变更，并提供时间线回溯。

- 列表、排序与分页
  - 使用服务器端分页，默认每页 20 条。
  - 默认排序为"最近更新"（按 updated 时间倒序）。
  - 支持在返回列表时保留筛选与滚动位置。
  - 提供"紧急申请清单"专门视图（见"紧急度评分"）。【P1】
- 状态与流转
  - 初始：加入"待申请"时自动设置状态为 Pending，并记录时间戳。
  - 主状态流转：Pending → Tailoring → Ready → Applied → Phone Screen → Interviewing → Offer → Rejected。【P0核心状态 + P1扩展状态】
  - Phone Screen（电话沟通）：完成初步电话/视频沟通，进入正式面试前的筛选阶段。【P1】
  - 每次状态更新均记录时间与变更记录（审计轨迹），可附加用户备注。
- 唯一性与去重
  - 同一用户与同一 Job 仅允许存在一条申请记录（user + job 唯一）。
- 筛选
  - 支持按状态、公司、地点、用工类型、添加/更新时间区间筛选。
  - 不提供统计数据分面，仅基础筛选与清空操作。
- AI 研究与定制 【P0】
  - 用户点击加入申请列表的时候，自动带出系统推荐的简历模板，用户可以自由选择简历模板，根据用户预设的定制需求进行定制。用户确认后新增申请记录，状态为Pending，触发后续流程。
  - Pending阶段：自动触发公司研究、定制简历（基于用户选择的简历模板的副本）、Cover Letter生成（依赖job信息+定制简历+公司研究）。
  - **简历定制分级**：引入可配置的定制深度：
    - **深度定制 (Deep Tailoring)**：全面重写个人简介、工作经历与职责，紧密对齐 JD 要求。
    - **轻度定制 (Light Tailoring)**：仅做最小调整，主要是关键词对齐与特定声明（如搬家意向）补充。
    - 用户可在申请时选择本次定制的策略（默认为Profile中预设偏好）。
  - 需要显式状态标记显示进行中/完成/失败（见"进度展示"）。
  - 失败自动重试（系统策略），不提供手动重试。
- 进度展示（阶段型）【P0】
  - 阶段：Research → Tailored Resume → Cover Letter → Quality Check。
  - 每阶段显示：Queued / Processing / Completed / Failed。
  - 整体完成度以阶段汇总显示。
- 材料质量检查 【P0】
  - 在Cover Letter生成完成后，自动触发质量检查：
    - 公司名称一致性：检查Cover Letter中的公司名是否与job匹配，若不一致标记警告。
    - 技能匹配度验证：检查定制简历中的技能是否覆盖job必备要求，若覆盖率<70%标记提示。
    - 文件命名规范：下载PDF时自动生成专业文件名格式：`{UserName}_Resume_{JobTitle}.pdf`与`{UserName}_CoverLetter_{JobTitle}.pdf`。
  - 检查结果在材料详情页展示，用户可选择忽略或修正后重新生成。
- 材料与版本化 【P0】
  - 定制简历为简历模板的副本，申请前可修改；申请后（状态≥Applied）定制简历锁定不可修改。
  - 简历模板的后续修改不影响已生成的定制简历。
  - 支持多次生成，保留历史版本（时间戳与参数快照）。
  - 提供下载 PDF 的能力（定制简历与Cover Letter）。
  - 生成历史可查看与对比。
- 备注与时间线
  - 申请支持备注；备注记录时间戳并纳入时间线。
  - 时间线包含：状态变更、备注、研究与材料生成事件。
- 面试准备（自动触发）【P1】
  - 当申请状态变更为Interviewing时，系统自动生成面试准备材料：
    - 公司常见面试题：基于公司研究，提炼该公司技术面试的常见题型与关注点。
    - 技术知识点复习清单：基于job必备技能与可选技能，生成技术复习大纲（含推荐资源链接）。
    - STAR行为面试准备：从用户所有简历模板中提取相关工作经历，生成STAR格式（Situation/Task/Action/Result）的行为面试答案草稿。
  - 面试准备材料为跨job共享资源，存储在用户级别，随着申请增加持续维护与更新。
  - 同一公司的多个申请共享公司面试题库；相同技能要求的job共享技术复习清单。
  - 用户可手动编辑与补充面试准备材料，修改记录时间戳并版本化。
- 操作 【P0】
  - 单条操作：一键标记Applied、添加备注、打开职位原始链接、调整定制简历（仅限状态<Applied）并下载PDF版本。
  - 批量操作：支持批量标记为Applied状态。
- 删除与过期
  - 删除申请为软删除，当用户再次申请相同岗位时，恢复该条记录。
  - 职位外链失效或职位过期暂不特殊处理（不自动变更状态）。
- 展示密度与详情
  - 列表卡片显示：职位标题、公司、地点、状态、最近更新、研究/材料阶段进度、操作入口。
  - 详情页展示完整时间线与材料版本列表；Interviewing状态显示面试准备材料入口。【P1】
- 国际化与文案
  - UI 文案使用英文；保留未来国际化扩展能力。
- 限制与边界
  - 使用分页；暂不考虑速率限制与每日配额展示。

### 进度可视化
- 进度可视化看板 【P1】
  - 提供Kanban风格的可视化看板，按状态分列展示申请（Pending/Tailoring/Ready/Applied/Interviewing/Offer/Rejected）。
  - 支持拖拽卡片在列之间移动以快速更新状态。
  - 看板顶部显示统计数据：总申请数、各状态数量、本周新增申请数、面试转化率等。
- 里程碑庆祝 【P2】
  - 当用户达成特定里程碑时（申请第10/50/100个职位、获得第1/5/10个面试、收到首个Offer），显示庆祝动画与鼓励消息。
  - 里程碑记录在用户Profile中，支持回顾历史成就。

## 网络拓展与内推机会 【P2】
协助用户通过人脉网络提升申请成功率，从冷申请转向温暖介绍。

### LinkedIn集成与联系人匹配 【P2】
- LinkedIn账号授权连接：用户可选择授权连接LinkedIn账号，同步一度与二度人脉数据。
- 目标公司员工匹配：当用户浏览job或加入"待申请"时，系统自动检测用户LinkedIn人脉中是否有该公司员工。
- 匹配结果展示：在job详情页与申请详情页显示"你的联系人：张三（Software Engineer，一度人脉）"。
- 内推请求辅助：针对匹配到的联系人，提供内推请求消息模板生成功能：
  - 基于用户与联系人的关系（前同事/校友/共同兴趣）个性化开场白。
  - 结合job信息与用户背景，说明为何适合该职位。
  - 礼貌请求内推或行业建议，避免过于直接。
- 隐私保护：用户可选择关闭此功能；匹配数据仅本地处理，不上传至服务器。

### 行业活动与社区推荐 【P3】
- 基于用户目标公司、岗位与技能，推荐相关的线下/线上活动（Meetup、技术分享会、行业会议）。
- 活动日历集成：用户可将感兴趣的活动加入个人日历，设置提醒。
- 参会跟进：活动后提示用户添加备注（认识了谁、获得了什么信息），纳入申请时间线。

### GitHub/作品集优化建议 【P3】
- 当job强调代码能力或作品集时，系统分析用户GitHub（或其他代码托管平台）项目。
- 提供优化建议：如"建议在简历中突出XX项目，与job要求的YY技术高度匹配"。
- 项目README优化：针对目标岗位，生成项目介绍的优化版本，突出相关技术栈与业务价值。

## 用户Profile 【P0】
支持用户设置申请时的默认定制需求，在加入"待申请"时自动带出并可修改。
- 定制需求预设：用户可预设简历定制偏好（如强调技术深度、管理经验等）和Cover Letter风格偏好。
- **默认定制深度**：用户可设置默认的定制策略偏好（深度定制或轻度定制），在申请时自动应用。
- 自动带出：在"我的申请"Pending阶段，系统自动填充这些预设值，用户可针对具体岗位调整。
- 里程碑记录：存储用户达成的里程碑成就（见"里程碑庆祝"）。【P2】
- LinkedIn授权状态：记录用户是否授权LinkedIn集成（见"网络拓展与内推机会"）。【P2】

## 简历
### 简历管理 【P0】

支持多份简历的维护与编辑，围绕"草稿 → 正式版本（简历模板）"的流程管理，并提供 AI 分析与建议的可选增强。UI 文案使用英文，保留未来国际化扩展能力。

- 数量与限制
  - 每位用户可维护多份简历。
  - 正式（非草稿）简历上限为 3 份/用户（可配置）；草稿数量不作硬性限制（受大小约束）。
- 基础字段
  - 名称（必填，用户内唯一）、内容（Markdown 纯文本）、是否草稿（is_draft）。
  - 使用场景记录在"我的申请"中，不在简历对象内累积统计。
- 新建与定稿
  - 新建简历默认保存为草稿，可多次修改与保存。
  - 定稿后成为"正式版本"（作为简历模板），仅正式版本可用于申请时推荐与选择，也可计算与job的匹配度。
  - 正式版本（简历模板）仍可修改，但不影响已生成的定制简历副本。
- 编辑与预览
  - 在线编辑与实时预览（Markdown → HTML）。
  - 若组件支持，可“对比查看变更”（如查看 AI 修改内容）；若无则不强制。
- 导入与导出
  - 允许上传/导入 .md；允许下载 .md 与 .pdf（沿用默认主题样式）。
- 自动保存与版本
  - 提供本地自动保存（草稿自动保存到浏览器本地）。
  - 支持手动保存版本；版本对比功能暂不提供。
- 删除与引用约束
  - 删除为软删除；若被申请引用（存在定制简历副本依赖），禁止删除简历模板。
- 样式与版式
  - Markdown 仅支持默认主题，暂不提供排版增强（目录/分栏/高亮等）。
  - 保留主题扩展能力（未来可新增）。

### AI定制简历 【P0】
- AI 分析与优化建议（简历管理模块）【P1】
  - 支持"一键分析"，并允许用户输入自定义提示词后再分析。
  - 分析生成多条建议（标题+简述），用户可勾选后"一键应用"。
  - 应用时尽量保留原文对照（侧边或分栏对比），取决于组件能力。
  - 建议范围由内置 Prompt 定义（措辞优化、量化成果补充、结构微调等）。
  - 暂不限制每日分析次数。
- 定制与岗位关联 【P0】
  - 岗位定制仅在"我的申请"中进行；"简历管理"不直接生成岗位定制版本。
  - 申请流程中：系统将分析所有"正式"简历与 JD 的匹配度，并标记最佳匹配的简历（Recommended_Resume_ID）。
  - **推荐与追踪**：
    - 系统需明确记录系统推荐的简历 ID (`Recommended_Resume_ID`) 与用户最终选择的简历 ID (`Selected_Resume_ID`)。
    - 目的：用于后续分析用户偏好与系统推荐的准确性。
  - 每次应用的建议可作为简短备注写入该版本元信息中。
- 列表与排序
  - 简历列表按"最近更新"排序，一次性展示（不分页）。
  - 允许复制简历，但需提供新名称；同一用户下名称不可重复。
- 内容类型与大小
  - 仅支持 Markdown 纯文本内容，大小不超过 100KB。

### 简历技能分析 【P0】
当用户的简历定稿的时候，通过llm分析用户的工作经历和技能情况，更新用户的技能库。包括用到的技术，以及每种技术的熟练程度，熟练程度标准化为几个等级。除了硬技能，还包括软技能和行业经验等。允许用户添加新的技能并修改技能等级。


## 用户角色与配额管理 【P0】
用户分为多个角色，普通用户、VIP用户、管理员，各角色具有不同的功能权限与使用限制。

### 角色权限 【P0】
- 普通用户：正式简历上限3份，每月申请job数量20个，AI使用量受限。
- VIP用户：正式简历上限10份，每月申请job数量不限，AI使用量更高配额。
- 管理员：无限制，可查看系统统计数据与用户使用情况。

### 配额统计与限制 【P0】
- AI使用量按模型分别统计：包括调用次数与token数量。
- 达到上限时的行为：无法新增正式简历、无法触发AI定制流程、无法使用AI分析功能。
- 配额重置周期：每月1日重置月度配额（申请数量、AI使用量）。
- 配额展示：用户Profile页面显示当前配额使用情况与剩余额度。【P1】
